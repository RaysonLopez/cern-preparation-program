# Reporte Semanal: Flujo de Trabajo Colaborativo en GitHub

## Descripción de la Actividad
Durante esta semana se implementó y ejecutó un flujo de trabajo colaborativo utilizando Git y GitHub. El objetivo técnico de la actividad fue gestionar el control de versiones dentro de un equipo de desarrollo, asegurando que múltiples colaboradores puedan alterar un mismo proyecto de forma simultánea manteniendo la integridad y organización del historial de código.

**Material de referencia de la semana:** 
[GitHub Skills: Review Pull Requests](https://github.com/skills/review-pull-requests)

## Fases del Flujo de Trabajo Ejecutado

Para cumplir con los requerimientos de la actividad, se aplicaron los siguientes procesos de control de versiones:

1. **Gestión de Ramas (Branches):** 
   Se crearon ramas independientes a partir del entorno principal (`main` o `master`). Esto permitió aislar el desarrollo de nuevas características o correcciones sin afectar el código de producción.

2. **Registro de Cambios (Commits):** 
   Se empaquetaron las modificaciones locales mediante commits, incluyendo descripciones precisas sobre las alteraciones realizadas en los archivos del repositorio.

3. **Propuesta de Cambios (Pull Requests):** 
   Se abrieron solicitudes de extracción (Pull Requests) para notificar al equipo sobre las modificaciones listas para ser integradas. Este paso expone las diferencias exactas (diffs) entre la rama de trabajo y la rama principal.

4. **Revisión de Código (Code Review):** 
   Se realizó la validación cruzada del código. Integrantes del equipo auditaron los Pull Requests generados por otros desarrolladores para aprobar los cambios, sugerir modificaciones o identificar posibles conflictos técnicos antes de la integración.

5. **Integración de Contribuciones (Merge):** 
   Una vez aprobada la revisión técnica, se ejecutó la fusión (Merge) de la rama de trabajo hacia el repositorio principal, unificando el código y cerrando el ciclo de la tarea.
